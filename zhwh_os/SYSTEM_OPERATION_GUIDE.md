# Hillson OS System Operation Guide

This guide describes the basic command-line operations available in the
Hillson OS desktop terminal.

## 1. Terminal Basics

Type a command in the terminal and press **Enter**.

To display the built-in command list:

```text
help
```

To clear the terminal:

```text
clear
```

To print text:

```text
echo hello
```

## 2. Listing Files

List the system root directory:

```text
ls /
```

List the contents of the USB drive:

```text
ls /usb
```

The directory `/usb` is the FAT32 USB-drive mount point. Files shown by
`ls /usb` are files on the USB drive itself.

For example:

```text
/usb/granite.gguf
/usb/USB_AI.LOG
```

## 3. System Files and USB Files

The following files are system-memory files provided by the RAM filesystem:

```text
/kern.log
/usb.log
/console.log
```

They are not files on the USB drive.

The USB drive is mounted separately:

```text
/usb/
```

Therefore, the USB log file is accessed as:

```text
/usb/USB_AI.LOG
```

## 4. USB Status

Check the USB initialization state:

```text
usb status
```

The command reports whether the USB subsystem and mass-storage device are
ready.

The command below is retained for compatibility with the kernel USB
interface:

```text
usb init
```

USB initialization is normally managed by the kernel during system startup.

## 5. Viewing the USB Driver Log

Display the current USB driver log held in the system memory buffer:

```text
usb log
```

This command does not read a file from the USB drive. It displays the latest
USB diagnostic messages currently held in the in-memory ring buffer.

The equivalent RAM log path is:

```text
/usb.log
```

## 6. Saving the USB Log to the USB Drive

Make sure the USB drive is ready:

```text
usb status
```

Save the current USB log snapshot to the USB drive:

```text
usb log save
```

The save command performs the following operations:

1. Captures the current USB log buffer.
2. Creates `USB_AI.LOG` in the USB drive root directory if it does not exist.
3. Allocates FAT32 data clusters when needed.
4. Writes the complete snapshot to the file.

The resulting file is:

```text
/usb/USB_AI.LOG
```

Verify that the file exists:

```text
ls /usb
```

A successful save prints:

```text
Saved to /usb/USB_AI.LOG
```

## 7. Important Save Behavior

The log is saved as a snapshot. It contains messages collected before the
save operation begins.

The disk-writing process itself performs USB transfers. Diagnostic messages
generated by those transfers are not recursively appended to the same save
operation. This prevents the log file from being rewritten indefinitely.

To capture a new final state, run the command again:

```text
usb log save
```

## 8. Reading a Saved Log

After saving, verify the file is present:

```text
ls /usb
```

Use the normal file-reading command if supported by the current terminal
build:

```text
cat /usb/USB_AI.LOG
```

If the terminal does not provide `cat` output for a FAT32 file, remove the
USB drive safely and read `USB_AI.LOG` on another operating system.

## 9. Recommended USB Log Workflow

Use this sequence when collecting diagnostics:

```text
usb status
usb log
usb log save
ls /usb
```

Expected result:

```text
USB_AI.LOG
```

## 10. Troubleshooting

### `ls /usb` does not show the log file

Check the USB state:

```text
usb status
```

Then run:

```text
usb log save
```

If saving fails, the USB drive may not be mounted, may not be FAT32, or may
be write-protected.

### `kern.log` or `usb.log` cannot be found on the USB drive

This is expected. These are RAM filesystem files. The file written to the
USB drive is:

```text
/usb/USB_AI.LOG
```

### The terminal repeatedly prints `transfer`

USB transfer messages are diagnostic output from the USB controller. They
are not the name of the log file and do not mean that the log command itself
must run forever. Wait for the transfer to complete, then issue:

```text
usb log save
```

### The USB drive contains `granite.gguf`

That confirms `/usb` is showing the real USB-drive root directory. The log
file should appear beside it after a successful save:

```text
granite.gguf
USB_AI.LOG
```

## 11. Command Summary

| Command | Purpose |
|---|---|
| `help` | Show the terminal command list |
| `ls /` | List the system root directory |
| `ls /usb` | List files on the USB drive |
| `usb status` | Show USB initialization state |
| `usb init` | Query the kernel-managed USB initialization interface |
| `usb log` | Display the in-memory USB driver log |
| `usb log save` | Save the USB log snapshot to `/usb/USB_AI.LOG` |
| `cat /usb/USB_AI.LOG` | Read the saved log when supported |
| `clear` | Clear terminal output |
